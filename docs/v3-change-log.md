# V3 / specification 2.1

The user supplied V3 of the private specification and explicitly reiterated that no access credentials are wanted. The application remains public with no sign-in, password, session or login requirement. This overrides the inherited login section of the specification. The private Markdown is excluded from Git, build source uploads and exports.

The functional tool name is **Samsung CRM Activation Studio**. **Luna** is the product. Project Luna remains only in source provenance; the legacy PROJECT_LUNA identifier migrates to product_id LUNA without changing source record IDs.

The original Samsung PNG was acquired from the explicit sample source at res6.it.email.samsung.com. Original bytes are preserved locally, pinned by SHA-256, visually inspected and recorded in src/brand/logo-manifest.json. No redraw, AI generation, recoloring, filter, crop or proportion change is used. Its source/asset verification is separate from final campaign approval, clear-space measurements, fonts and licensing review.

Tool chrome and visual proof exports carry the original lettermark. Email sender display name is Samsung. Push notifications identify Samsung Members / Samsung Shop in their native text-only sender chrome, without fabricated app icons, verification badges or a raster logo in the OS payload. WhatsApp sender identity is Samsung; platform verification is not claimed.

New deterministic QA blocks missing/unverified logos, missing output identity, altered proportions and product naming mismatch. It preserves human brand/product/legal review. The Luna product image remains a clearly labelled asset-pending slot, distinct from the now-present Samsung logo.

Activation handoff uses a same-origin server API, a canonical creative-only package and an internal MarketingOpsAdapter interface. Stensul is the primary destination. The alternative Marketing Operations platform is unspecified. Mock and manual modes are implemented; live adapter classes fail closed with explicit prerequisites, never an invented API URL or vendor capability.

The mock processes one server batch, exposes per-item outcomes, idempotency keys, checksums, source/mapping versions and simulated partial / timeout / rate-limit / permission failures. Manual export is labelled manual import required. There are no remote IDs, URLs, real asset transfers, remote drafts, approval, scheduling or sends. Unknown outcomes do not trigger an automatic retry.

Receipt history is explicitly browser-local demo persistence, with the latest outcome counted per creative idempotency key. It is not a durable live job database or authoritative vendor state. A verified, authorized tenant contract, module/media mappings, service permissions, durable store, role enforcement and operator confirmation are prerequisites for any future live draft adapter. No credentials or infrastructure were provisioned.
